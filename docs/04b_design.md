# 04b. Дизайн сайта (визуальный язык и экраны)

Дополнение к `04_ux_scenario.md`: здесь — визуальная система, компоненты и экраны. UX-сценарий — в `04`.

## 1. Направление дизайна (решение D-13)

**«Родной для ТМК, лёгкая форма».** Берём брендовый характер заказчика (графит, оранжевый `#EC6608`, condensed-заголовки, плоские заливки, прямые углы, тонкие линии), но делаем продукт **плотнее, спокойнее и читабельнее**, чем их сайты. Это сочетает узнаваемость для жюри и удобство инструмента.

Рассматривались и отклонены:
- «Аналитическая панель» (Linear/Vercel-стиль) — качественно, но без связи с заказчиком.
- «Диспетчерская» тёмная — эффектно, но хуже читаются таблицы и формулы.

## 2. Принципы дизайна

1. **Плотность со спокойствием.** Плотные таблицы и KPI, но строгая сетка, без визуального шума. 32px строки таблиц, 14px базовый текст.
2. **Никаких «голых» чисел.** Каждое число — диапазон, у каждого числа есть путь к формуле и источнику. Это видно, а не спрятано.
3. **Промышленный, а не стартапный.** Без градиентов, «стеклянных» карточек, теней и скруглений. Разделение — плоскими заливками и 1px-линиями (`research/18`).
4. **Проверяемость визуально.** Извлечённые параметры выглядят иначе, чем подтверждённые; расчётные числа иначе, чем введённые; источник виден у всего.
5. **Оранжевый — цвет действия и метки, никогда статус.** Статусы — отдельная RAG-шкала, чтобы «предупреждение» не смешивалось с фирменным цветом (`research/18`, §C13 п. 3).
6. **Сравнение — главный графический приём.** Два сценария всегда рядом, одним цветом каждого.

## 3. Цвета

Светлая тема (основная). Тёмная — P2, не делаем.

### 3.2. Семантика (RAG) и серии данных

| Токен | HEX | Роль |
|---|---|---|
| `good` | `#2F6B4F` | высокая уверенность, «в коридоре» |
| `warn` | `#D98E1F` | средняя уверенность, предупреждение |
| `bad` | `#C0392B` | низкая уверенность, риск |
| `info` | `#2A5D8F` | нейтральная заметка |
| `series-inhouse` | `#0072B2` | **внутренняя команда** на всех графиках |
| `series-contractor` | `#D55E00` | **подрядчик** на всех графиках |
| `series-hybrid` | `#009E73` | **гибрид** |
| `risk` | `#C0392B` | надстройка риска поверх столбца |

Правила:
- Цвет никогда не единственный носитель смысла: рядом всегда текст или иконка.
- Оранжевый занимает ≤ 2 % площади экрана (`research/18`).
- Серии подписаны на графике напрямую, без легенд, где серий ≤ 3.

## 4. Типографика

| Слой | Шрифт | Лицензия |
|---|---|---|
| Заголовки панелей, KPI | **Barlow Condensed** (DIN-подобный, свободный аналог PF DIN) | OFL |
| Текст интерфейса, таблицы | **Inter** | OFL |
| Числа, формулы, ID | **JetBrains Mono** или IBM Plex Mono | OFL |

Все шрифты — локальные файлы, без CDN (NFR: работа без внешних ресурсов).

Шкала (продуктовый UI, 14px база):

| Токен | Размер / интерлиньяж | Начертание | Применение |
|---|---|---|---|
| `metric-lg` | 36–40 / 1,0 | Condensed 700, tabular | главное число вердикта (стоимость) |
| `metric` | 28–30 / 1,0 | Condensed 700, tabular | KPI вердикта |
| `h1` | 30 / 1,05 | Condensed 700, UPPERCASE | заголовок страницы |
| `h2` | 22–24 / 1,15 | Condensed 700, UPPERCASE, оранжевый | заголовки панелей («ОЦЕНКА», «СРАВНЕНИЕ») |
| `h3` | 16 / 1,3 | Inter 600 | карточки, подзаголовки |
| `body` | 14 / 1,45 | Inter 400 | основной текст |
| `body-s` | 13 / 1,4 | Inter 400 | таблицы, списки |
| `label` | 11 / 1,2, +0,08em | Inter 600 UPPERCASE | подписи полей, шапки таблиц |
| `micro` | 11 / 1,3 | Inter 400 | единицы, даты, источники |
| `mono` | 13 / 1,5 | Mono 500 | формулы, коды, ID |

Все числа в таблицах и KPI — `font-variant-numeric: tabular-nums`, выравнивание по правому краю, единица — в шапке или в `micro` рядом.

## 5. Сетка, отступы, форма

- Сетка кокпита: колонки **320 / 1fr / 360 px**, верхняя полоса **56 px**, отступ 16 px между колонками, 24 px поля (на 1440×900).
- Сетка страниц: 12 колонок, 16 px gutter, 24 px margin, макс. 1440 px.
- Отступы: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64. Секции — 24–32 px (не 72–120 как на сайте ТМК, `research/18` C13 п. 1).
- **Радиус: 0** везде (карточки, кнопки, чипы, таблицы). Исключение — 2 px у полей ввода.
- **Тени: нет.** Разделение — 1px-линии и плоские заливки. Тени только у выпадающих: drawer/modal `0 12px 32px rgba(17,17,17,.14)`.
- Фокус: 2px контур `#EC6608` с отступом 2 px.
- Плотность таблиц: строки 32 px, текст 13 px, сетка `border-strong`, без «зебры».

## 6. Экраны

SPA, четыре экрана:

| # | Экран | Назначение |
|---|---|---|
| 1 | **Старт** | вход: новая оценка, демо D1–D3, список сохранённых |
| 2 | **Кокпит** (рабочий экран) | бриф → вердикт → сравнение → экспорт |
| 3 | **Данные** | датасеты, источники, версии, качество, импорт HelpDesk |
| 4 | **Методика** | формулы, допущения, ограничения, что не умеем |

- Знак продукта — **свой** (квадрат с диагональю в духе бренда, но не логотип ТМК, `research/22` §12). Подпись «для ТМК++» текстом.

### 6.2. Кокпит (главный экран)

Полная схема зон — в `04_ux_scenario.md` §3. Здесь — визуальная обработка.

**Верхняя полоса (56 px, тёмная `band-dark`):**
- слева: название оценки, сценарии-чипы `[Команда][Подрядчик][Гибрид][+]`;
- справа: переключатель точности, бейдж «Данные v0.3 · дата», `Экспорт PDF`, `XLSX`, `Снимок`.

**Левый рельс «Бриф» (320 px, `surface`):**
- textarea с рамкой `border-strong`; кнопка `[Разобрать]` — оранжевая (primary);
- таблица проверки: строки 32 px, в колонке «источник» — цитата в кавычках (правила) или «Jev · 0,87» (вероятность), бейджи уверенности цветом + текстом;
- группы параметров (аккордеоны), чипы допущений (прямоугольные, `border`, при высокой чувствительности — метка `⚠`).

**Центр «Ответ»:**
- вердикт-полоса на `surface`: три KPI (трудоёмкость / срок / стоимость), каждое число — диапазон «800–1 080 / 930 / 3,9–5,8 млн» с `metric`-цифрами и `label`-подписями; Confidence Score с разложением при наведении; дисклеймер `micro` внизу.
- вкладки графиков (как в `04` §3): активная — оранжевое подчёркивание 2 px.
- детальная зона: смета по этапам и ролям (моноширинные числа), аналоги, риски, допущения, источники.

**Правый рельс «Сравнение» (360 px):**
- две карточки сценариев: рамка `border`, у победителя — 2px оранжевая метка слева **только как акцент действия**, а не как «статус» (выигрыш формулируется текстом и Δ);
- числа P50 крупно, диапазон `micro`; риск-премия отдельной строкой;
- break-even бейдж, краткая матрица, CTA `[Сформировать PDF]` — оранжевая.

**Drawer «Формула» (480 px, справа):** дерево расчёта, моноширинные формулы, у каждого узла источник с датой, кнопка «изменить» ведёт к полю.

### 6.3. Данные

Таблица датасетов: имя, строк, версия (хеш), дата, источник, статус валидации (RAG-бейдж). Импорт HelpDesk — отдельная карточка с дроп-зоной; после импорта — отчёт о качестве (сколько строк принято/отброшено и почему, таблицей). У каждого датасета — «открыть» с просмотром строк (read-only).

### 6.4. Методика

Статичная страница: цепочка расчёта (схема 5 шагов), формулы с пояснением, список допущений и их диапазонов, список источников, раздел «чего инструмент не делает». Это же содержимое попадает в PDF-приложение.

## 7. Компоненты

| Компонент | Внешний вид |
|---|---|
| Кнопка primary | оранжевая заливка, белый текст, UPPERCASE 12px +0,08em, высота 40 px, радиус 0 |
| Кнопка secondary | 1px `border-strong`, прозрачная |
| Чип (фильтр/сценарий) | прямоугольник 1px `border`; активный — **чёрная заливка**, белый текст (приём сайта ТМК); радиус 0 |
| Бейдж уверенности | рамка + текст: «высокая / средняя / низкая», цвет RAG + текст (не цвет один) |
| Карточка сценария | `border`, заголовок `h3`, числа KPI, спарклайн опционально |
| KPI-метрика | `metric`-число + диапазон `micro` + `label`-подпись UPPERCASE |
| Таблица | 32px строки, шапка UPPERCASE 11px на `surface`, сетка `border-strong`, числа вправо |
| Вкладки | UPPERCASE 13px, активная — оранжевый текст + 2px подчёркивание |
| Drawer | 480 px, тень, затемнение фона `rgba(17,17,17,.4)` |
| Входное поле | 2px радиус, `border-strong`, фокус — оранжевый контур |
| Документная строка | иконка + название + формат (PDF/XLSX) + длинная стрелка `—→` |
| Баннер предупреждения | жёлтая полоса RAG `warn` с текстом (не оранжевая) |

## 8. Графики

Библиотека: Recharts. Общие правила: подписи серий на графике, единица в заголовке оси, табличный режим у каждого, hover — перекрестие и значения, нулевая база для столбцов, без двойных осей.

| График | Что показывает | Оформление |
|---|---|---|
| **Break-even** | кумулятивные затраты двух сценариев по месяцам 0–36, точка пересечения | линия команды `series-inhouse`, подрядчика `series-contractor`; пунктирная вертикаль в точке + подпись «М6»; закрашенная область экономии после пересечения; одна фраза-аннотация |
| **Tornado** | какие допущения двигают итог | горизонтальные столбцы, сортировка по размаху; базовая линия по центру; концы с подписями значений |
| **Стек TCO** | затраты по годам, категориями | стек-область; итоговая линия сверху; категории — прямые подписи топ-3 |
| **Гистограмма распределения** | форма Монте-Карло | столбцы `text-secondary`, маркеры P10/P50/P80/P90 пунктиром, подпись «P80 — резерв бюджета» |

## 9. Состояния

| Состояние | Оформление |
|---|---|
| Пустой бриф | textarea + 3 демо-чипа, подсказка |
| Разбор идёт | прогресс-строка (тонкая оранжевая), числа остаются видимыми |
| Пересчёт | лёгкая пульсация KPI, числа не мигают |
| Не подтверждено | бейдж «12 параметров · 2 не подтверждены»; экспорт заблокирован с подсказкой |
| Методы расходятся | жёлтый баннер `warn` с объяснением |
| Устаревшие данные | бейдж «прейскурант от …, обновить» |
| Jev недоступна | бейдж «разбор: правила» + баннер `info` |
| Ошибка расчёта | сообщение с кодом, бриф сохраняется |

## 10. PDF-выгрузка

«Бумажная» версия системы (`research/04` §2.3): фон `#F7F6F3`, текст `#221C1C`, оранжевый только для заголовков разделов, шапка со знаком продукта и подписью «TMK Decision Studio · для ТМК++», колонтитулы: версия данных, дата, seed. Стр. 1 — решение; приложения — формулы, аналоги, допущения, риски, источники, методика. Числа — tabular.

## 11. Доступность

- Текст ≥ 4,5:1, крупный ≥ 3:1, границы ≥ 3:1 (использовать `border-strong` для таблиц).
- Каждый график — с кнопкой «таблица».
- Фокус видимый, полная работа с клавиатуры (P2 — полный набор горячих клавиш, в P0 — основные).
- Уменьшенное движение: без счётчиков-анимаций при `prefers-reduced-motion`.
