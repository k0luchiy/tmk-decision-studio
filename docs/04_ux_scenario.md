# 04. Пользовательский сценарий и интерфейс

Основано на `research/08_uiux_design_spec.md` и на регламенте (`research/22` §11). Дизайн-токены — `research/04`, `research/18`.

## 1. Пользователь

| Персона | Что делает в инструменте | Что ему важно |
|---|---|---|
| **Аналитик проектного офиса / экономист ИТ** (основной) | Вносит бриф, проверяет параметры, сравнивает сценарии, готовит документ для бюджета | Проверяемость цифр, аналоги, выгрузка |
| **Руководитель ИТ-проекта / служба заказчика** | Получает вердикт и коридор, решает «идти / не идти», «сами / подрядчик» | Вердикт за 30 секунд, риски, рубли |
| **Закупки** (вторичный) | Берёт аналоги и обоснование цены | ≥ 3 цены, коэффициент вариации, источники |

Момент использования: **между апробацией и бюджетом** (`research/13`, G3–G5). Инструмент не заменяет ТЗ, а отвечает на вопрос до него.

## 2. Сценарий «от идеи до документа» (полный, FR-9)

1. **Бриф.** Пользователь вставляет текст задачи или выбирает демо D1 / D2 / D3.
2. **Извлечение.** Система (правила, и Jev если включена) выделяет параметры и показывает таблицу проверки: параметр, значение, уверенность, цитата из текста или вероятность Jev.
3. **Подтверждение.** Пользователь принимает, правит или отклоняет параметры. Пока есть непроверенные поля, экспорт заблокирован.
4. **Расчёт.** Вердикт, сценарии, графики обновляются. Видно, что изменилось относительно предыдущего шага.
5. **Допущения.** Пользователь меняет одно допущение (например, ставку подрядчика) и смотрит, как сдвинулся итог и какое допущение сильнее всего влияет (tornado).
6. **Проверка числа.** Клик по любой цифре открывает формулу-дерево с источником и датой.
7. **Аналоги.** Таблица трёх и более аналогов с приведением и отметкой, что входит в медиану.
8. **Риски и уверенность.** Реестр рисков и Confidence Score с разложением.
9. **Выгрузка.** PDF (1 страница решения + приложения) и XLSX. Снимок с версией датасетов.

На защите полный сценарий занимает 90 секунд (раздел 7).

### 3.1. Зоны

| Зона | Содержание | Ключевые состояния |
|---|---|---|
| **A · Верхняя полоса** | Выбор сценария (базовый / команда / подрядчик / гибрид), переключатель точности, версия датасетов, экспорт | Сценарий «грязный» (есть правки) — точка; экспорт заблокирован до подтверждения брифа |
| **B · Бриф** | Текстовое поле, кнопка «Разобрать», таблица проверки, группы параметров (объём, команда, ставки, риски, сроки), чипы допущений | пусто / набор / разбор / разобрано / устарело (бриф изменён после разбора) |
| **C1 · Вердикт** | Три метрики (трудоёмкость, срок, стоимость) с диапазоном Мин / Средн. / Макс и уровнем уверенности; режим Estimate ⇄ Target | загрузка / готово / пересчёт / невозможно |
| **C2 · Вкладки графиков** | Break-even, сценарии, tornado, TCO, матрица решений | каждый с режимом «таблица» |
| **C3 · Вывод** | 1–3 сгенерированные фразы-ссылки («Подрядчик дешевле до месяца 6; дальше дороже на 0,3 млн в год») | клик фокусирует график |
| **C4 · Детали** | Смета по этапам и ролям, аналоги, риски, допущения, источники | вкладки |
| **D · Сравнение** | Карточки «Команда» и «Подрядчик» (P50 и диапазон, риск-премия, срок), Δ, break-even, краткая матрица, CTA | «победитель» отмечается, но вердикт формулируется условно |
| **Drawer 480px** | Формула-дерево по клику на любое число | узел: значение, формула, входы, источник, дата, «изменить» |

## 4. Слой «Бриф → параметры» (детально)

Таблица проверки — **главное доверие**: машина не угадала, а показала основание.

| Колонка | Содержание |
|---|---|
| Параметр | Название и тип (число, список, да/нет) |
| Значение | С единицей; редактируется |
| Уверенность | Высокая / средняя / низкая, текстом, не только цветом |
| Цитата | Фрагмент брифа, выделяется при наведении |
| Действие | Принять / править / отклонить (клавиши a / e / r) |
| Исходное | Значение, извлечённое системой, остаётся видимым после правки |

Правила:
- Параметр без цитаты (например, значение по умолчанию) помечается «по умолчанию», а не «из брифа».
- Отклонённый параметр возвращается к значению по умолчанию и помечается.
- Бриф изменён после разбора → баннер «3 параметра могут быть устаревшими, разобрать заново?». Молчаливого пересчёта нет.

## 5. Вердикт: что показываем и как формулируем

Формулировка вердикта в шаблоне (пример, D1):

> **Порядок стоимости 3,9–5,8 млн ₽ · срок 12–17 недель · уверенность 68 %.**
> Команда дешевле подрядчика на 0,1 млн ₽ за реализацию, но дороже на 0,3 млн ₽ в год на сопровождении. Точка безубыточности — месяц 6 эксплуатации. Рекомендация: гибрид — подрядчик на критическом пути (2 из 6 потоков), команда на остальном и на поддержке.

Правила формулировки:
- Всегда диапазон и уверенность, никогда одна цифра.
- Оба сценария, даже если один очевидно выигрывает.
- Слово «рекомендация» — только при выполнении условий из `03` §6.
- Внизу дисклеймер «оценка порядка, а не смета».

**Именование (из Q&A, R17):** на экране «Мин / Средн. / Макс», в деталях — P10 / P50 / P90 и P80 как «резерв бюджета». Жюри видит оба языка.

## 6. Визуальный стиль

Полная спецификация — в `04b_design.md`. Здесь — кратко:

- Родной для ТМК, но **плотнее** их сайта (`research/18`): знак и цвет `#EC6608` только для CTA и заголовков панелей; графит `#111` для текста; серый `#6B6B6B`; хайрлайн `#D6D6D6` (для функциональных границ — `#9A9A9A`).
- Радиус 0, тени не используются (кроме выпадающих окон), плоские заливки.
- Заголовки панелей — condensed uppercase (свободный аналог PF DIN: **Barlow Condensed** или **D-DIN**, лицензии OFL / свободная), текст — **Inter** или системный гротеск, цифры — tabular-nums.
- Оранжевый ≤ 2 % площади. Для мелкого оранжевого текста — `#B4470A` (контраст 4,6:1).
- Семантика RAG отдельно от брендовых цветов: зелёный / жёлтый / красный — для уверенности и рисков. Цвет не единственный носитель смысла (иконка и текст).
- Серии графиков: внутренняя команда — синий `#0072B2`, подрядчик — `#D55E00` (палитра Okabe-Ito, различима при дальтонизме), каждая линия подписана.
- Логотип ТМК **не** используется как элемент бренда продукта (`research/22` §12). Продукт — «TMK Decision Studio» со своим знаком. Можно упомянуть «для ТМК++» текстом.

## 7. Демо-сценарий на защите (90 секунд + 4 минуты)

| Время | Действие | Что закрываем |
|---|---|---|
| 0:00–0:20 | Проблема одним слайдом: «решают на глаз; калькулятор — без рисков; AI — без проверки» | понимание кейса |
| 0:20–1:30 | Жюри даёт задачу (или выбираем D2 из трёх заготовок). Вставка текста → таблица проверки → подтверждение | полный сценарий, прототип |
| 1:30–2:10 | Меняем одно допущение (ставка подрядчика или срок) на глазах жюри → пересчёт, вердикт и tornado | работающий расчёт |
| 2:10–2:40 | Клик по цене → формула-дерево с источником и датой | проверяемость |
| 2:40–3:10 | Три аналога с приведением, расхождение методов | рыночная оценка |
| 3:10–3:30 | Риски, резерв P80, уверенность и почему она именно такая | объяснимость |
| 3:30–3:50 | PDF на экране: «документ, который прикладывается к бюджету» | ценность для бюджета |
| 3:50–4:30 | Границы: что не умеем, что калибруем на пилоте, какие данные не получили | честность, защита |

Запасной план: если демо падает, — заранее сохранённый снимок (`Снимок`) D1 с PDF и видео 60–90 секунд (`07_action_plan.md`).

## 8. Экспорт

| Формат | Содержимое | Примечания |
|---|---|---|
| **PDF** (P0) | Стр. 1: решение (вердикт, сравнение, break-even, допущения-ключевые, уверенность, дисклеймер). Приложения: формула-дерево, аналоги с приведением, риски, источники, версия датасетов, seed и дата | Печатный стиль, нумерация, колонтитул «версия датасетов · дата» |
| **XLSX** (P1) | Листы Scenarios, LineItems, Assumptions, Risks, Sensitivity, Analogues, Sources | Значения и формулы, не плоский дамп |
| **JSON** (P1) | Полный снимок оценки (вход, версии, результаты) | Воспроизводимость: из JSON можно повторить расчёт |
| **Снимок** (P1) | Замороженная ссылка с баннером «снимок от …» | — |

Экспорт — вычисляемое состояние: недоступен, пока не подтверждены поля с флагом (`08_uiux` §4.6).

## 9. Состояния и обработка ошибок

| Ситуация | Что видит пользователь |
|---|---|
| Бриф слишком короткий | «Не хватает данных: уточните тип работы, число интеграций, срок». Расчёт в классе «порядок величины» |
| Нет подходящих аналогов | Аналоговый метод отключён, в вердикте: «аналогов < 3, диапазон расширен» |
| Методы расходятся > 30 % | Жёлтый баннер с указанием, какой метод сдвигает оценку |
| Срок короче базового | Предупреждение и надбавка по `E ∝ t^(−4)` |
| Ставка устарела | Бейдж «прейскурант от …, обновить» |
| Нехватка грейда в in-house | Предложение найма: цикл 45–65 дней + ramp-up в сроке |
| Подрядчик дешевле на 3 года, дороже на старте | Оба вывода, условный вердикт, точка перехода |
| Сбой Jev | Работает правиловый разбор; баннер «разбор без Jev» |
| Сбой расчёта | Понятное сообщение с кодом ошибки, данные брифа сохраняются |

## 10. Адаптивность интерфейса

- Ширина ≥ 1280: три колонки. 1024–1279: бриф в выдвижной панели, сравнение внизу. < 1024: один столбец. Печать: один лист.
- Режимы точности (FR-1.6) открывают или скрывают поля: при режиме «порядок величины» видны 5–6 полей; при «детальном» — полная декомпозиция.
- Пользовательские статьи затрат и этапы добавляются кнопкой «+» в соответствующих группах (R2, R8, R9).
