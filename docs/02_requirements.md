# 02. Требования

Источники: кейс (`research/01`), регламент и рубрика (`research/22`), протокол Q&A (`research/21`, требования R1–R20), схема HelpDesk (`research/20`).

Обозначения приоритета: **P0** — без этого демо не работает (делаем в первую очередь); **P1** — сильно повышает оценку; **P2** — если останется время.

## 1. Функциональные требования

### FR-1. Ввод и intake задачи

| ID | Требование | Приоритет | Приёмка |
|---|---|:-:|---|
| FR-1.1 | Поле свободного текста описания задачи (ТЗ, пользовательская история, письмо). Вставка, автосохранение | P0 | Принимает ≥ 2000 символов, не теряет текст при перезагрузке |
| FR-1.2 | Структурированные параметры: тип работы, платформа/стек, число интеграций, ролей, экранов, NFR, срок, ограничения | P0 | Все поля имеют значения по умолчанию, ни одно не блокирует расчёт |
| FR-1.3 | Извлечение параметров из текста. Правила (числа, словарь) всегда; Jev — классификация типов работ и флагов | P0 | Каждый извлечённый параметр имеет цитату из текста (правила) или вероятность (Jev); уровень уверенности обязателен |
| FR-1.4 | **Таблица проверки извлечённого.** Пользователь подтверждает или правит каждый параметр. Без подтверждения ничего не применяется молча | P0 | Расчёт не меняется без явного действия пользователя; видно, что изменено |
| FR-1.5 | Режим **Estimate ⇄ Target**: задан бюджет или срок → какой объём и состав помещаются | P1 | Обратный расчёт даёт допустимый объём при заданных ограничениях |
| FR-1.6 | **Уровень точности** задаётся доступными данными: порядок величины (только бриф) → бюджетный (есть декомпозиция) → детальный (есть объёмы и ставки) | P0 | Класс точности показан на вердикте; при его падении расширяется диапазон |
| FR-1.7 | Уточняющие вопросы при неполном брифе («не хватает данных: уточните X, Y») | P1 | Список конкретных вопросов, не отказ |

### FR-2. Расчёт затрат и сроков (ядро)

| ID | Требование | Приоритет | Приёмка |
|---|---|:-:|---|
| FR-2.1 | Декомпозиция по **единому шаблону этапов** (см. `03_estimation_model.md` §2) | P0 | Один шаблон для обоих сценариев |
| FR-2.2 | Трудоёмкость по этапам и ролям (аналитик, разработчики, QA, DevOps, ПМ, архитектор, ИБ, UX) с ≥ 2 грейдами | P0 | Разбивка по ролям и итог совпадают |
| FR-2.3 | Трёхточечная оценка O/M/P на каждый элемент → E и σ | P0 | Сумма E и дисперсий корректна |
| FR-2.4 | Диапазон стоимости и сроков: **Мин / Средн. / Макс** (P10 / P50 / P90), плюс P80 как резерв бюджета | P0 | Монте-Карло ≥ 10 000 итераций с корреляцией ролей ≥ 0,5 |
| FR-2.5 | Срок: критический путь, календарь РФ, загрузка команды | P1 | Срок не равен «трудоёмкость / команда» |
| FR-2.6 | Предупреждение при сжатии срока (закон Путнама / эластичность) | P1 | Сжатие > 25 % даёт предупреждение и надбавку |
| FR-2.7 | Подключаемые статьи затрат: инфраструктура, лицензии, оборудование, GPU/LLM-токены, поддержка | P0 | Добавление статьи пересчитывает итог; статья имеет источник или пометку «допущение» |
| FR-2.8 | Пересчёт при изменении любого допущения | P0 | Пересчёт < 300 мс; видно, что изменилось |
| FR-2.9 | Три метода размера с триангуляцией: bottom-up (основной), FP-lite (параметрический), аналоговый | P1 | Расхождение > 30 % показывается, не усредняется молча |

### FR-3. Сравнение «внутренняя команда vs подрядчик»

| ID | Требование | Приоритет | Приёмка |
|---|---|:-:|---|
| FR-3.1 | Два сценария с **разными базами затрат**: in-house fully loaded и contractor rate card. Оба развёрнуты по статьям | P0 | Нет «магической суммы» |
| FR-3.2 | Сценарий **Гибрид**: набор этапов, которые делает подрядчик, и этапов, которые остаются внутри, плюс поддержка внутри | P0 | Гибрид считается из той же декомпозиции |
| FR-3.3 | Сравнение по осям: стоимость, срок старта, срок завершения, гибкость, передаваемость знаний, ИБ/IP, управляемость, риск | P0 | Таблица «что сравнивали» с весами (Σ = 100, редактируются) |
| FR-3.4 | Break-even: месяц, когда накопленные затраты сравниваются | P0 | График кумулятивных затрат с отметкой точки |
| FR-3.5 | TCO на 1 / 3 / 5 лет: поддержка, лицензии, сопровождение, уход подрядчика | P0 | Стек по годам + таблица |
| FR-3.6 | Качественные выводы: глубина vs широта экспертизы, мобильность, онбординг, передача поддержки | P1 | 3–5 текстовых выводов под таблицей, каждый с основанием |
| FR-3.7 | Стоимость простоя (bench) и ФОТ после окончания проекта для in-house | P1 | Видно как отдельная строка TCO |
| FR-3.8 | NPV с настраиваемой ставкой | P2 | Ставка показана отдельно, с обоснованием |
| FR-3.9 | Честный вердикт: если подрядчик выигрывает на старте и проигрывает на 3 года, показываются оба | P0 | Вердикт формулируется условно, с точкой перехода |

### FR-4. Рыночные аналоги (reference class)

| ID | Требование | Приоритет | Приёмка |
|---|---|:-:|---|
| FR-4.1 | Подбор **≥ 3** сопоставимых записей по типу работы, объёму, региону, давности | P0 | Список аналогов с критериями отбора |
| FR-4.2 | Приведение аналога к объекту: коэффициенты объёма, сложности, региона, давности (инфляция), НДС | P0 | Каждый коэффициент виден и редактируем |
| FR-4.3 | Медиана и диапазон аналогов как **перекрёстная проверка** параметрической оценки | P0 | Если расхождение > X % — предупреждение |
| FR-4.4 | У каждого аналога: источник, URL/реестровый номер, дата, тип цены (НМЦК / победная / контракт), признак НДС | P0 | Нет аналога без источника |
| FR-4.5 | Ставки подрядчика по ролям и грейдам, модель контракта (T&M / fixed price / dedicated team) | P0 | Переключатель модели меняет структуру риска |
| FR-4.6 | Пометка базы данных: «НМЦК первого лота, не победная цена; НДС не расщеплён» | P0 | Видна в UI и в PDF |

### FR-5. Допущения и риски

| ID | Требование | Приоритет | Приёмка |
|---|---|:-:|---|
| FR-5.1 | **Реестр допущений:** название, значение, диапазон, источник, чувствительность | P0 | Чипы в UI, карточка с редактированием |

## 2. Нефункциональные требования

| ID | Требование | Как проверяем |
|---|---|---|

| NFR-7 | **Локализация:** русский язык, ₽, российский формат чисел | Визуальная проверка |

| NFR-9 | **Лицензии:** только MIT / Apache-2.0 / BSD / ISC / OFL; никаких коммерческих шрифтов (PF DIN), ISBSG-данных, секретов в репозитории | Чек-лист `research/22` §12 |
| NFR-10 | **Персональные данные:** в репозитории нет ФИО и контактов; выгрузка HelpDesk обезличена | Проверка перед пушем |
| NFR-11 | **Пересборка данных** из исходников скриптом (`data/datasets/*`) | Скрипт в `scripts/` |

## 6. Чего не требуем (`research/01` §3)

- ИИ/ML как таковой. Jev — только для классификации брифа, с подтверждением человеком; числа и текст — правила и шаблоны.
- Интеграцию с SAP / 1С / Jira / ЭТП в реальном времени.
- Учёт полного жизненного цикла сверх TCO 1/3/5 лет.
- Multi-tenant SaaS.
